# 推荐重复机制排查 · 2026-10-09

这轮处理的是点过“没兴趣”的活动换措辞再出现，以及清理后旧候选回流。此前只调整提示和排序不足以解决：应用自己的展示、回退和存储也有漏洞。

## 已确认的原因

- 无来源活动的 ID 由标题生成。旧排除检查匹配 ID、标题、网址或命名作品，换句话就能获得新 ID；“随慢歌松肩颈”和“随慢歌把身体松一遍”会绕过它。
- 选择器先找新内容，但不足三个时放宽活动冷却，最后重用已看缓存和本地预设。去重只有优先级，缺少最终禁止回流的边界。
- 模型没有合格结果或调用失败时，服务端把未经过模型筛选的搜索素材直接当作公开来源推荐。浏览器联调实测复现了营销视频、缺少介绍的书与英文菜谱组成三张卡片，解释了为什么改过提示后仍会退回看视频、看书和做饭。
- 点踩后原卡片留在当前页面，只重建后台候选。再次点同一个“没兴趣”会撤销反馈，页面容易让人误以为操作没生效。
- 反馈原来最多 120 条，超出时静默丢弃较早反馈。已看历史与普通缓存另有上限；依赖这些短期缓存排除不能保证持久。
- 漫游数据仍在浏览器本地。同一账号换设备或浏览器不会得到另一处的反馈；内置浏览器的反馈列表不能证明截图所在浏览器保存了什么。

## 这次改变的边界

- 对 Serenity 做一次按账号清理：保留收藏、正反馈和已有记录引用的完整快照，其余旧推荐缓存移开。记录引用只保留详情，不作为推荐候选。旧预设从推荐入口排除，但已有收藏和记录详情仍可读取。
- 清理前保存可恢复备份，“我的”提供清理和恢复入口。每次确实删除新缓存时更新备份；对空缓存重复清理不会覆盖可恢复副本。恢复只合并候选，不倒退之后的记录、反馈或配色。备份保存失败、存储冲突时取消清理。
- 只保留标题、简介、来源等最小排除依据；不保留这些被移开活动的推荐理由和开始步骤。排除依据不进入推荐卡片，用来挡住换措辞、换来源或换分类的副本。
- 点踩立即移开当前卡片，保留另外两张；有合适的新候选就补位，否则等待补充。重复点击同一反馈不撤销，撤销放在“我的”的明确入口。
- 客户端与服务端都执行排除检查。最近的负反馈和清理样例也传给模型，明确这些是排除项，不能当作灵感；喜欢唱歌不能据此推断喜欢随歌拉伸或“偏好安静”。关闭个性化仍执行明确排除。
- 已配置模型时，搜索素材只供模型筛选，失败、无新结果和全部被排除时均不直接发布这些素材。原因如实显示；未配置模型的基础公共来源模式保留，并明确来源身份。
- 清理后的模式禁止用旧、已看或仍在冷却的候选补齐。新组凑齐三个后展示，不足时明确等待新内容。后台批次和晚到响应受账号、条件、反馈与清理标记隔离；旧备份导入也不能重开旧候选入口。
- 反馈上限扩至 1000；达到上限时明确提示，不静默删旧反馈。备份合并超限会取消导入。排除依据单独保存，上限 1500。

## 验证与限制

- 新增截图两种措辞的回归测试，覆盖换 ID、分类、网址，刷新、清理、导入和后台候选；同时检查歌唱、具体舞蹈、瑜伽和不同作品仍可推荐。
- 测试清理失败不删数据、账号隔离、恢复只合并候选、反馈超过旧上限不丢失，以及来源验证和仅有排除结果时不填旧卡片。
- 本地浏览器联调用刻意反复返回两条旧活动的模拟模型，验证实际点踩、换组、保存、清理与恢复。此测试验证程序边界，不代表真实 DeepSeek 已提高推荐质量。
- 相同活动的判定仍是作品、来源、标题相似度与特定行动的规则，无法保证识别所有自然语言改写。不能据此宣称完全无重复或所有新活动都符合兴趣。
- 没有提交、推送、部署或修改真实模型密钥。线上浏览器中的实际旧数据，要在新版发布后打开同一浏览器完成自动迁移；其他浏览器各自执行。跨设备同步尚未实现，见 [云同步检查](cloud-sync-audit.md)。
