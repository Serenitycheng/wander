北京去哪儿玩 重构修改说明
目标：从“去哪儿玩工具”重构为“自由探索工具”

一、重构原因

当前“北京去哪儿玩”这个方向太窄，容易把产品做成普通的“地点推荐/出行决策工具”。

但我真正想要的，不只是“今天去哪里玩”，而是：

当我感到生活局限、陷入熟悉惯性、又想保持自由时，给我一个进入探索状态的入口。

所以，这个产品后续不应再仅仅围绕“北京去哪儿玩”展开，而应升级为一个更广义的：

自由探索 / 随机探索 / 打破惯性 / 扩展生活边界 的工具。

它可以包含“去哪儿玩”，但不能只等于“去哪儿玩”。

二、新定位

1. 产品定位

这是一个帮助用户摆脱熟悉惯性、进入自由探索状态的轻量工具。

它的作用不是：
- 做详细旅行攻略
- 做高密度打卡系统
- 做严肃任务管理
- 做效率工具

它的作用是：

在用户“不知道现在想做什么，但不想继续陷在熟悉生活里”时，提供一个低门槛、轻推动、非强制的探索入口。

2. 核心价值

它要解决的不是“没有推荐”，而是：
- 想探索，但不知道从哪开始
- 想打破生活惯性，但启动困难
- 空闲时间很多，最后总是回到最熟悉的娱乐
- 想自由一点，但又不想被新系统重新束缚

所以这个产品的核心不是“安排”，而是：

帮助进入自由，而不是管理自由。

三、产品理念

1. 轻，不压迫
不要像任务管理软件。
不要让用户一打开就看到很多待办、统计、目标、连续天数、完成率。

2. 给入口，不给束缚
产品只负责提供一个探索入口。
至于用户最后探索多久、探索到哪里、有没有结果，不做强约束。

3. 随机，但不是无意义随机
随机探索不是“乱推内容”，而是提供有趣、可执行、可打破惯性的选择。

4. 探索不限于“出门”
探索应该包括：
- 去新的地方
- 看新的东西
- 学新的主题
- 做新的小项目
- 尝试新的体验
- 在家进行的小型探索

5. 不把自由再做成 KPI
不要过度打卡、量化、成就系统。
这个产品应该保护自由感，而不是消耗自由感。

四、重构后的核心方向

1. 从“地点探索”升级为“自由探索”
原产品中的“北京去哪儿玩”保留为一个子模块，而不是全部。

新的探索范围至少包括四类：

A. 地点探索
- 去一个没去过的地方
- 公园 / 街区 / 展览 / 建筑 / 小店 / 市集 / 咖啡馆 / 图书馆 / 散步路线

B. 居家探索
- 看一本平时不会主动看的书/文章
- 听一张专辑
- 看一部平时不会选的电影/纪录片
- 尝试做一道新东西
- 整理一个主题收藏
- 拍一个主题照片

C. 学习探索
- 随机了解一个陌生领域 30 分钟
- 学一个很小的技能
- 看一个新的知识主题
- 做一个小型知识卡片/笔记

D. 创作 / 项目探索
- 写一点东西
- 画一点东西
- 做一个小页面/小组件
- 开一个很小的项目分支
- 做一个微型创作实验

五、产品结构

1. 首页：探索入口页

首页不要像工具列表，更不要像任务面板。
首页应该非常轻，重点是让用户“想点一下”。

首页核心内容建议只有四块：

（1）今日入口
一句轻提示 + 一个主要按钮。

例如：
- 今天要不要去点没做过的事？
- 想不想打破一下惯性？
- 给我一个探索入口

按钮可以是：
- 开始探索
- 随机一下
- 今天做点新的
- 随便带我去一个地方 / 一件事

（2）探索模式选择
建议保留：
- 出去走走
- 在家探索
- 学点东西
- 做点东西
- 完全随机

（3）最近收藏 / 想试试
展示少量收藏，不要像长清单。

（4）探索记录
只展示最近几次，不强调统计。

2. 探索生成页（核心页）

第一步：你现在想怎么探索？
- 出门
- 在家
- 学习
- 创作
- 随机

第二步：你现在大概有什么条件？
- 10～30 分钟
- 1～2 小时
- 半天
- 无所谓

第三步：当前状态
- 想轻松一点
- 想有点新鲜感
- 想认真投入一点
- 完全随缘

然后只给出 1～3 个建议。
不要一次给很多。

每个建议需要足够具体，可立即执行。

例如：
- 去某个街区走一圈，顺便拍三张“今天的光线”
- 在家看一篇关于陌生主题的长文
- 听一张没听过的专辑，并记录一句感受
- 打开你的某个项目，做一个 20 分钟微改动
- 去一家没去过的书店待半小时

3. 具体建议详情页

每个建议点开后，页面只需要三件事：

（1）这是什么
一句说明，不要太长。

（2）为什么适合你现在
比如：
- 启动成本低
- 适合一个人
- 不需要准备
- 有新鲜感
- 适合想打破熟悉惯性的时候

（3）如何开始
给一个非常小的开始动作。

例如：
- 直接出门
- 打开地图
- 带上耳机
- 搜索某个主题
- 新建一个文档
- 打开项目文件夹

不要写成攻略文档。
重点不是信息密度，而是启动。

4. 收藏 / 想试页

这个页面不是待办清单，而是“以后也许会想试”的轻量存放处。

设计上建议：
- 分组收藏：出去 / 在家 / 学习 / 创作
- 可以标记“最近想试”
- 不设 ddl
- 不做完成率
- 不做任务压力

5. 记录页

记录页不能像打卡软件。
它的作用只是：帮用户看见自己确实在拓展生活边界。

建议只保留：
- 做了什么
- 当时感觉如何
- 是否还想继续类似探索

可选字段：
- 时间
- 地点
- 一句话感受
- 一张照片

不要复杂统计。
不要做成“成长看板”。

六、UI / 美术风格重构方向

新的 UI 应该更偏向：

轻、留白、安静、柔和、带一点诗意和探索感。

关键词：
- 轻盈
- 自由
- 流动
- 呼吸感
- 留白
- 柔和
- 非功利
- 带一点文艺 / 诗意感
- 不要强商业感

不建议的方向：
- 过于鲜艳
- 过于互联网工具感
- 过于攻略网站
- 过于打卡社区
- 过于效率软件
- 信息堆叠太满

建议的视觉表达：
- 大留白
- 卡片少而精
- 柔和背景色
- 页面元素疏朗
- 插画/抽象图形可适量使用
- 可以偏“城市漫游 + 自由想象 + 轻诗意”的氛围

UI 感受应该接近：
“今天想不想去试一点新的？”

而不是：
“来完成任务”。

七、命名重构建议

“北京去哪儿玩”过于直白，也把产品限制死了。

如果重构为更广义的自由探索工具，建议改名。

方案一：偏自由探索感
- 随便看看
- 去试试看
- 乱逛一下
- 随机一下
- 去看看
- 今天做点新的
- 随便去哪里
- 未定
- 闲游
- 漫游一下

方案二：偏诗意 / 文艺感
- 游离
- 漫游
- 流动
- 留白
- 远一点
- 出走一下
- 未至
- 轻游
- 漫行
- 余白

方案三：功能 + 气质平衡
- 自由探索
- 今日探索
- 随机探索
- 探索一下
- 城市漫游
- 探索入口
- 今天去哪 / 今天做什么
- 轻探索

更推荐的主产品名候选：
- 自由探索
- 今日探索
- 探索一下
- 去试试看
- 漫游
- 余白

“北京去哪儿玩”可以保留为其中一个子模块。

八、建议的页面结构

方案 A（更简单）
- 首页
- 探索
- 收藏
- 记录
- 我的

方案 B（更有结构）
- 今日
- 探索
- 城市
- 收藏
- 我的

更推荐方案 A，更轻。

九、核心功能优先级（MVP）

第一阶段不要做太多。

必做：
1. 首页轻入口
2. 探索模式选择
3. 随机生成 1～3 个探索建议
4. 北京地点探索子模块
5. 收藏功能
6. 简单记录功能

第二阶段再考虑：
1. 按时间/心情/预算筛选
2. 附近探索
3. 主题探索
4. 更丰富的内容库
5. 个性化推荐

暂时不要做：
1. 强社交
2. 打卡竞赛
3. 连续签到
4. 复杂成就系统
5. 重度攻略内容
6. 重任务管理功能

十、产品边界

这个产品不是：
- 序流
- 学迹
- 旅游 App
- 攻略社区
- 自律打卡工具

这个产品应该是：

一个帮助我从熟悉惯性中脱身，轻轻走向更自由生活的入口。

十一、最终重构结论

这次重构的核心，不是“把北京去哪儿玩做得更丰富”，而是：

把它从“去哪儿玩工具”升级为“自由探索工具”。

最终方向应是：
- 地点探索只是其中一部分
- 产品核心是帮助用户打破惯性
- 页面设计要轻，不压迫
- UI 要有自由感、留白感、诗意感
- 不要再做成一个新的任务系统
- 产品只负责提供探索入口，不负责接管用户的自由时间
