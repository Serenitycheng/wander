# 漫游跨设备云同步检查

检查日期：2026-10-09。本报告核对当前本地源码与线上「我的」页面；没有读写生产数据库或更改线上配置。

## 结论

**漫游尚未实现跨设备云同步。** 同账号登录只确定空间身份，探索数据仍保存在各设备的浏览器中。已有的 Neon 云空间服务属于旧北京出行模块，漫游没有调用它。

- 收藏、最近想试、记录：本机保存，支持手动备份。
- 赞踩、偏好清单、兴趣、书单、推荐开关：本机保存；换设备不会自动继承反馈。
- 全站底色、自定义配色方案：本机保存；换设备不会自动恢复。
- 已展示条目、作品去重历史、在线详情快照：本机保存；换设备可能再推荐旧作品，直接打开在线详情也可能找不到快照。

刷新和同浏览器重新登录可以沿用本机数据，不能证明云同步。不同浏览器、设备和域名都有独立的数据；预览部署和正式域名也不能自动共享。

## 代码与页面证据

- `source/src/features/exploration/components/exploration-app.tsx` 从 `window.localStorage` 读取、保存空间，通过 `storage` 事件接收同浏览器其他标签页的更新。没有探索空间的云端读取或提交。
- `source/src/features/exploration/storage.ts` 使用 `free-exploration:space:v1:serenity|zzz`；`types.ts` 的整个 `ExplorationSpace` 包含上述收藏、记录、偏好、配色、反馈和推荐历史。
- `source/src/features/exploration/components/me-page.tsx` 备份导出为 JSON，导入调用本地合并。线上「我的」页面也明确显示「收藏和记录保存在这个浏览器里」。备份不等于自动同步。
- `/api/exploration/discover` 用条件与偏好生成推荐，不持久保存探索空间；给模型发送偏好不等于账号云端存储。
- `source/src/app/api/workspace/route.ts` 接受旧 `TripDraft`，要求 `draft.id` 和 `draft.answers`；`source/src/lib/server/workspace.ts` 写入 `beijing_play_workspaces` 和版本表。新探索数据没有写入这些表。
- 旧 `features/beijing/components/city-experience.tsx` 才调用 `/api/workspace`，并受登录、数据库配置和原云端共享开关控制。本次没有确认其生产配置与跨设备运行状态。

## 同时修改的现状

- 本机修订号检查能阻止已经过期的标签页直接覆盖较新内容；不是云端事务，也不能处理两台设备的修改。
- 手动导入保留本机已有记录、反馈和偏好，补充缺失收藏、记录、快照、历史与配色方案。它没有同步协议、字段级冲突处理或删除标记，不能作为实时云同步使用。
- 目前不存在可供验证的「两台设备同时修改漫游」云流程，因此没有把本机测试写成跨设备同步通过。

## 后续接入需要完成

1. 使用单独的探索数据接口和表，继续按登录账号授权；不改写旧北京云空间。
2. 登录后拉取云端数据，修改后提交；保留本机缓存、离线待提交队列、失败重试和清楚的同步状态。
3. 同步收藏、记录、反馈、偏好、配色方案和去重历史；保留被收藏或记录引用的在线快照。
4. 用服务端修订号检测冲突，按项目或字段合并；删除与撤销反馈需要同步删除标记，避免旧设备把内容复活。不采用整份空间直接覆盖。
5. 迁移前备份，先合并各设备已有数据；保留恢复渠道和账号隔离。
6. 用两个独立浏览器验证登录恢复、离线重连、同时增改删、撤销反馈、配色、已看历史、账号切换和登录失效。网络请求与数据库结果共同作为通过证据。

本次完成检查与方案整理，没有新增或发布云同步实现。
